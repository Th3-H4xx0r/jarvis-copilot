# 2026-10-12 — ESP32 relay keeps its Bluetooth bond

- [x] **1. "iOS still holds old pairing keys" on the ESP32 every ~2 days.** He said: "This should be fixed so
  the key NEVER expires so I don't have to keep doing this every 2 days".
  - Cause (ESP-IDF v5.5 source): Bluedroid erases a peer's bond, in RAM and in flash, on any failed SMP or
    encryption (`bta_dm_act.c` BTM_LE_COMPLT_EVT, `btc_dm.c` auth complete), and iPhone-started encryption
    goes through SMP (`smp_act.c` `smp_link_encrypted`, "for example iPhones"). One failed re-encryption at
    the edge of range wiped the board's keys while iOS kept its own. The board had 2d 3h of uptime, so no
    reboot was involved. There is no Kconfig switch, and the stack ships as a prebuilt library.
  - Fix: firmware 1.2 `BondKeeper` keeps a copy of the stack's bond store (`bt_config.conf` → `jc_bt_copy`).
    When a saved bond disappears it reboots and writes the copy back before Bluetooth starts (stops after 3
    tries with no successful encryption between them). The app retries for 30 s after "peer removed pairing
    information" before showing the "forget the board" message.
  - ✅ Live on his board + phone: a temporary test build erased the bond like a failed encryption → phone hit
    `pairing failed (0x66)` → `[bond] … rebooting to put it back` → `put back … (475 bytes)` → the new app
    reconnected with its old key ("paired and encrypted", ANCS receiving; no new copy written = no re-pair).
    Final firmware (no test hook) flashed, and the phone relinked. Host test `tests/bond_store_test.cpp` ✓.
