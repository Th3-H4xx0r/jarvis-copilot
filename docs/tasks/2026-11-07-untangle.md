# Untangle the codebase — 2026-11-07

Goal: pieces that change together live together, pieces that don't aren't tied,
and everything depends on what changes less. Extras chosen: **Comments** and **Tests**.

Scope by leverage (120-day churn): `webui/api` first (routes/voice/streaming are the
top three churned files), then the iOS app (Voice, Shell, Ring, Dashcam, Live).
The upstream-derived core (`gateway/run.py`, `cli.py`, platform adapters) changes
rarely and can no longer merge from upstream anyway, so it comes last.

Baseline: HEAD `f300f3e196`, webui suite run serially (no xdist in `.venv`).

## Wave 1 — server (`webui/api`)

### Fixes, each above the problems it solves

1. [ ] **One mount table for feature routers.** Each feature module that already exposes
   `handle_X_request(method, sub, body, …)` is mounted once, by prefix, in one list;
   the dispatcher runs it for every HTTP method with one request object (path, sub-path
   with query, parsed query, lazy body, host signature, caller). `handle_get/post/put/
   patch/delete` stop repeating the wiring.
   - `api/routes.py` repeats the prefix-strip + call + `j()` block 32 times across
     `handle_get` (3561), `handle_post` (5022), `handle_put`, `handle_patch`, `handle_delete`
     (7260) — car, door, island, harnesses, widgets, agent-notes, coding, dashcam, live.
   - `routes.py:7273` comment: coding DELETE "was only wired into handle_get/handle_post,
     so DELETE fell through to a generic 404" — a new method needs a new copy per feature.
   - The copies have drifted: door GET appends `?query`, door POST drops it; dashcam GET
     passes `parse_qs` but not the raw query; island POST passes a `token_store`, GET
     doesn't; coding fires `coding_events.notify()` after POST/DELETE inline.
   - 321 function-local `from api…` imports inside `routes.py`, most of them repeated per
     method for the same feature.
   - `routes.py` is the #1 churned file (72 commits/120d): every feature edits it.

2. [ ] **A chat-turn service with explicit turn options.** `api/chat_turns.py` owns
   "start a turn on a session" and "cancel a turn"; callers (HTTP chat, voice, live,
   harness jobs) pass a `TurnOptions` value instead of stashing attributes on the
   Session for `streaming` to find and clear.
   - `voice.py` imports `routes._start_chat_stream_for_session` and
     `routes._resolve_compatible_session_model_state` — a feature reaching into the
     HTTP dispatcher's privates (and `routes` imports `voice`: a cycle).
   - `harness_runner.py:845` calls `streaming._run_agent_streaming` directly.
   - Per-turn options travel as private Session attributes set by one module and read +
     cleared by another: `_turn_harness_id`, `_turn_explicit_model`, `_turn_surface`,
     `_turn_node_override`, `_turn_origin_directive`, `_voice_turn_directive`,
     `_voice_turn_low_reasoning` (`streaming.py:221-242`, `4359-4431`; set in
     `voice.py`, `routes.py`, `harness_runner.py`). Forget to clear one and it leaks into
     the next turn.
   - `streaming.py ↔ voice.py` co-change 12×, `routes.py ↔ streaming.py` 11× in 120 days.

3. [ ] **Shared plumbing lives below the features that use it.**
   - `_ENV_LOCK` (guards process-global `os.environ`) lives in `streaming.py`, so
     `profiles`, `providers`, `oauth`, `onboarding` import the most volatile module for a lock.
   - `_sse` (write one SSE frame) is in `streaming.py`; `live_ws` and `routes` import it.
   - `_check_csrf` is in `routes.py`; `live_ws` imports it from the dispatcher.
   - `auth._check_host_signature` is imported privately by 6 call sites — it is public API.
   - `voice._reconstruct_http_request` / `voice._try_import_stt` are used by `live_ws`.
   - 150 distinct private names are imported across modules in `webui/api`.

4. [ ] **One place decides where feature state lives.** A profile-aware
   `state_dir()` + an atomic JSON read/write helper; the stores use them.
   - `harness_store.py:91`, `widget_store.py:114`, `island_store.py:352`,
     `dashcam_store.py:1345`, `dashcam_relay.py:112` each re-read `HERMES_WEBUI_STATE_DIR`
     with their own `~/.jarviscopilot/webui` fallback; `config.py:44` already computes
     `STATE_DIR`.
   - 31 hardcoded `".jarviscopilot"` paths across 12 modules (breaks profiles, per AGENTS.md).
   - Atomic tmp+`os.replace` JSON writes are re-implemented in ~13 modules
     (`island_store._write_json` is also borrowed by others).
   - Three "active home" getters: `providers._get_hermes_home` (imported 7×),
     `rollback._hermes_home`, `brief_sources._home`, each with a different fallback.

7. [ ] **One provider-alias table.** Three exist and disagree: `routes._PROVIDER_ALIASES`
   ("gemini"→"google", a provider *family* map — now `session_model._PROVIDER_FAMILY_ALIASES`),
   `config._PROVIDER_ALIASES` ("google"→"gemini", a hand copy of `jarviscopilot_cli/models.py`'s
   table "for installs without the agent tree" — impossible in this monorepo), and the CLI's own.
   Same for `_PROVIDER_MODELS` / `_PROVIDER_DISPLAY` in `config.py` vs the CLI catalogue.

8. [ ] **Features own their whole slice of routes.py.** Still embedded in the dispatcher:
   approvals (SSE registry, subscribe/notify, stream, pending, inject, respond — `api/clarify.py`
   is already the colocated twin), session deletion (`delete_chat_session`, imported by `live_ws`),
   the phone energy journal (`_append_energy_report`), cron run tracking, insights, handoff
   summaries, manual compression jobs, media serving. Each becomes its own module / mount.
