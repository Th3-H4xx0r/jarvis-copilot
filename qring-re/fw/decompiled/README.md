# RT12_3.10.06 — decompiled and annotated C

Readable reconstruction of the ring's running firmware `base_RT12_3.10.06_260429.bin`
(Colmi/YaWell R12, Realtek RTL8762, Cortex-M Thumb-2).

| File | What |
|---|---|
| `RT12_3.10.06.c` | **read this** — 1,519 functions in address order, real names, a `// What:` description on every function, a subsystem index at the top |
| `RT12_3.10.06.raw.c` | Ghidra's untouched output (regenerated by the headless scripts) |
| `functions.csv` | address, name, size, callers, callees, description |
| `strings.csv` | string literals with addresses |
| `../ghidra/annotate/names.py` | the hand-derived names + descriptions (256 functions, 41 ROM routines, 145 globals) |
| `../ghidra/annotate/annotate.py` | raw → annotated: renames, fixes the switch case labels, adds comments and the index |

Regenerate: run `../ghidra/scripts/ExportRT12.java` headlessly (see `../README.md`), then
`python3 ../ghidra/annotate/annotate.py`.

## How to read it

- The top of the C file is an **index by subsystem** (boot, hub task, BLE handlers, transport,
  accelerometer, gesture, heart-rate, pedometer, config store, ...).  Jump to a function by
  searching for its name or for `@ 0x0082xxxx`.
- Every function header has `// Module:` and `// What:`.  A description ending in `[auto]`
  was generated from the callees/strings/globals and is a hint, not a reading.
- Naming evidence, strongest first: *verified* (code read), *signature* (matches the Realtek
  SDK prototype), *from string* (the function's own log tag).  `names.py` says which.
- `rom_*` / `os_*` / `flash_*` / `log_*` functions live in the chip's mask ROM and have no
  body here.  `gap_ipc_call` is the ROM entry behind ~180 thin BLE-stack wrappers.
- Command handlers are named `cmdNN_<app name>` using the app-side protocol names from
  `../../notes/sdk-protocol.md`; "(app-task)" in the description means the command is queued
  and handled by `cmdq_drain` instead of inline in `ble_cmd_dispatch`.
- ARM `switch8` jump tables (22 of them) confused the decompiler; `annotate.py` re-parses the
  byte tables from the binary and rewrites the `case` labels to the real values (e.g. the
  command ids in `ble_cmd_dispatch`).  A comment on each `switch(` names the table address.

## Where to start

| Want | Function |
|---|---|
| boot | `entry_trampoline` → `reset_handler` → `app_modules_init` |
| a BLE command | `ble_cmd_dispatch` (fast path) and `cmdq_drain` (app-task path) |
| what the ring sends on its own | `send_device_notify` (0x73 types), `send_camera_event` |
| accelerometer / taps | `accel_probe_chip`, `accel_configure_tap`, `accel_gesture_enable`, `gsensor_process_samples` |
| gesture strength (cmd 0x3B) | `cmd3b_touch_gesture_setting` → `gesture_set_settings` → `accel_gesture_enable` |
| heart rate / SpO2 | `cmd69_start_measurement` → `hr_post_start` → `hr_module_cmd` → `hr_measure_start` |
| settings in flash | `cfg_add_item`, `cfg_find_item`, `cfg_write_to_flash` (magic 0x8721BEE2) |
| time | `cmd01_set_time`, `rtc_now_seconds`, `app_minute_tick` |

## Things learned while naming (see the descriptions for detail)

- **The accelerometer driver supports five chips** and picks one at boot by WHO_AM_I:
  0x11 (SC7A20, LIS3DH-compatible register map, I2C 0x19), 0x28, 0x44 (LIS2DW12), 0x23
  (I2C 0x1F) and 0x48 (I2C 0x20).  A genuine LIS3DH (0x33) is *not* accepted by `accel_init`.
  The `lis3dh_spi.c` path string names the module, not necessarily the part.
- **Tap detection is done in the sensor**, not in software: `accel_configure_tap` programs
  CLICK_CFG/CLICK_THS (LIS3DH map) or TAP_THS_X/Y/Z (LIS2DW12).  The app's gesture
  *strength* (cmd 0x3B, 1..10) only reaches registers on the LIS2DW12 and chip-0x23 paths; on
  the LIS3DH-compatible path CLICK_THS is a fixed 5.
- **Shake-to-shoot** is software: in camera mode, >10 consecutive samples above magnitude
  0x7d1 send cmd 0x02 / 2 ("take photo") with a 3 s cooldown (`gsensor_process_samples`).
- **`motor_vibrate` is an empty stub** — no motor on this hardware.
- **Blood pressure is synthesised** from heart rate plus random jitter (`bp_synthesize`).
- The "wrong signature!" check is the **config page magic**, not an OTA signature.
- Slow commands go through a 10-slot queue to the app task; TX is a 128-slot ring flushed by
  `tx_drain`; big-data (0xBC) frames are CRC-16/MODBUS checked in `bigdata_rx_complete`.

## Caveats

- 117 KB of 137 KB is inside functions; the rest is data.  Decompiler output is a
  reconstruction: odd `CONCAT44(...)` returns and `extraout_r1` are artefacts of unknown
  calling conventions, not behaviour.
- Ghidra's `crc16_modbus` body shows an empty loop; read the disassembly for that one.
- Names are applied to the exported text by `annotate.py`; the Ghidra project still shows
  `FUN_*`.  To make them stick in the GUI, import `names.py` there.
